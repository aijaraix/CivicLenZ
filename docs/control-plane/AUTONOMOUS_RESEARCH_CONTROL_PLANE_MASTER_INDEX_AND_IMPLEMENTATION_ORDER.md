# CivicLenZ Autonomous Research Control Plane — Master Index & Mandatory Implementation Order

## 1. Purpose
This document is the authoritative navigation, precedence, implementation-order and conformance index for the CivicLenZ autonomous research control plane.

It exists so Codex, Google/Gemini, HERMES, OpenClaw, engineers, operators and future producers do not selectively read isolated documents, implement only their vocabulary, or create parallel interpretations of the research organization.

The system must be implemented as behavior, not as architecture-shaped status objects.

## 2. Canonical repository and authority
Canonical repository: `aijaraix/CivicLenZ`.

Canonical CivicLenZ/HERMES owns canonical work authority, identity resolution, validation, current-state reconciliation, contradiction state, publication eligibility and public projection.

`aijaraix/CivicsLenZz` and future producers remain subordinate research producers. Their strongest default positive output state is `extracted_unreviewed` until canonical processing occurs.

## 3. Mandatory proof doctrine
Every material implementation claim follows:

`REQUIRED_BEHAVIOR -> ACTUAL_EXECUTION -> DURABLE_EVIDENCE -> INDEPENDENT_VERIFICATION -> CLAIM`.

The following are never sufficient by themselves:
- a class/function name
- configuration
- registration
- a local file
- a status string
- a heartbeat
- a unit test
- a generated trace
- a generated hash
- a generated evidence object
- a local build
- an unpushed Google workspace commit
- a sender-written acknowledgement

## 4. Mandatory reading rule
Before materially changing autonomous research behavior, read this index, the current machine-readable manifest, and every manifest-required document applicable to the implementation.

Do not rely on prior conversation memory as a substitute for canon.

Record:
- canonical repository/ref/commit

- required document count

- contradictions/missing paths
- local-vs-remote-vs-deployed source state

## 30. Single-orchestrator rule
One canonical control plane; many workers/producers.

Codex and Google are engineering environments, not runtime authorities.

OpenClaw is a tool/browser runtime. Qwen/Gemini are model runtimes/providers. Cloudflare is execution fabric. Supabase is structured state. R2 is evidence storage. None independently becomes canonical HERMES by virtue of existence.

## 31. Shared VPS rule
A single CivicLenZ VPS may host multiple services if authority, resource, filesystem, secret and network boundaries are explicit.

Do not split authority by developer. Split execution by responsibility.

## 32. No fixed agent count
Logical capabilities are not physical agents. A registered capability does not prove a running worker.

For every capability report the implementing process/module, wakeup, queue, last real job, last retrieval/evidence, backlog and failure state.

## 33. No self-certification
A component may perform internal checks, but critical transitions require an independent attesting boundary whenever technically possible.

Examples:
- scheduler ledger attests dispatch
- queue consumer attests consumption
- storage verifier recomputes artifact hash
- receiver attests package receipt
- validator attests validation state
- projection service attests publication

## 34. Failure doctrine
Fix generalized first incorrect transitions, not visible records.

`incident -> trace -> root cause -> blast radius -> generalized repair -> supersession/regeneration -> regression -> monitoring`.

## 35. Preserve good work
When proof machinery is invalid:
- invalidate proof/status assertions
- preserve real retrievals/evidence
- classify unknown artifacts
- regenerate downstream status from real telemetry

Do not erase legitimate research merely because its former status was overstated.

## 36. Currentness doctrine
Historical sources cannot silently satisfy current-state requirements where authoritative current sources exist.

Person, Seat, Occupancy, CandidateCampaign, Election and lifecycle events remain distinct with valid-time semantics.

## 37. Backlog doctrine
A blank applicable scope requires a reason/state and next action. Research is backlog-driven, not prompt-driven.

## 38. Source-health doctrine
A configured source is not healthy until physically checked. UNKNOWN remains UNKNOWN.

## 39. Monitoring doctrine
Registration is not monitoring. Monitoring requires scheduled/event execution, physical retrieval/comparison, persisted result and follow-up work where needed.

## 40. Deployment doctrine
Source code, local workspace, GitHub and deployed runtime are separate states.

Always report:
- canonical contract commit
- implementation remote commit
- local runtime commit
- deployed artifact/runtime commit

## 41. Google/CivicsLenZz rule
Google must not create a parallel canonical organization.

CivicsLenZz may:
- research
- monitor producer-local sources
- maintain frontier backlog
- retain offline results
- submit authenticated packages

It may not self-validate, self-acknowledge receipt, publish canonical truth, or redefine canonical completeness/currentness.

## 42. Codex rule
Codex should focus on canonical/infrastructure-sensitive implementation and deployment. It must consume the same canon and prove that the resulting HERMES runtime survives the Codex session.

Do not spend Codex work recreating bulk research that producers can perform safely.

## 43. Cloudflare rule
Cloudflare Workers/Queues may scale lightweight work, but remain bound to canonical work identity/authority. Cron configuration alone is not execution proof.

## 44. Supabase/R2 rule
Supabase/Postgres is canonical structured durability where approved; R2 is evidence/object storage where approved. Neither is truth merely because a row/object exists.

## 45. OpenClaw/Qwen/model rule
Browser/model services must prove actual requests from authorized jobs. Service liveness is not utilization. Model output is not primary civic evidence.
